## 先说判断：双轨，两拨人，两套打法

| | A 轨 · 内容 | B 轨 · 社区 |
| --- | --- | --- |
| 人群 | 吃货，要的是「我吃过多少家」 | 工具党 / 开发者，要的是「这东西做得干净」 |
| 渠道 | 小红书 | V2EX、豆瓣小组、HelloGitHub、周刊、少数派 |
| 拿什么 | 曝光、收藏、第一条真实反馈 | Star、数据纠错、长期搜索长尾 |
| 内容形态 | 战绩图 / 清单图，**内容本身就能交付** | 技术取舍、开源介绍，可附完整链接 |
| 不追求 | 不在这一轨追求跳转和 Star | 不在这一轨追求吃货用量 |

这个分工不是拍脑袋：多个独立开发者的一手复盘里，工具帖在推荐流里普遍只有几百曝光、接近 0 转化；而**时间序社区**（V2EX、豆瓣小组）里小号的帖子照样能被看见，是种子用户和纠错的主要来源。反过来，只有「产品本身就是笔记内容」的形态（清单、模板、战绩图）才在小红书跑得动。

**本轮所有渠道口径统一**：开源免费、代码 MIT、数据单独声明、免登录纯本地。不提任何付费计划，不放任何形式的「求 star」。

| 渠道 | 轨 | 成本 | 判断 |
| --- | --- | --- | --- |
| 小红书 | A | 低（图已备好） | **首发，优先做** |
| 即刻 | B | 低 | 顺手发一条 |
| V2EX 分享创造 | B | 低 | **值得发**，别写成广告腔 |
| 豆瓣相关小组 | B | 低 | **新增，值得发**：时间序对新号友好，先看组规 |
| HelloGitHub | B | 低 | **已投**，月刊收录后持续进 Star |
| 少数派 Matrix | B | 中 | 值得投一次，用 `docs/announcement.md` 改 |
| 阮一峰周刊 | B | 低 | 值得投，要有「有意思」的角度 |
| 知乎 | B | 中 | 搜索长尾，有空再补 |
| 微博 / 抖音 | — | 高 | 不建议，需要持续运营 |

**一句话策略**：A 轨只管把内容做好、把评论区聊起来；B 轨拿 Star 和纠错。两轨各看各的数据，别拿同一把尺子量。

## 1. 小红书（A 轨 · 0 粉冷启动版）

这一版给**没有粉丝基础、也没有小工具上传权限**的账号写。核心不是「介绍一个工具」，而是**发一张战绩图**；也不是「把人引到站外」，而是**让笔记本身就能交付**。

小红书是兴趣推荐，不是粉丝分发——单篇曝光看首图和选题，不看粉丝数。但用新号发「我做了一个工具」，大概率没人点。所以顺序反过来：先用战绩勾住人，工具放最后一段。

**三条来自他人复盘的硬约束**（决定了这一版怎么写）：

- **「人」比「功能」有互动**：同一开发者三篇笔记，讲自己的故事拿了 49 个互动，讲功能只有 2 个（24 倍）。所以正文必须是第一人称。
- **具体数字带点击、不带互动**：数字能让人点进来，但让人评论的是「我的选择」或「一个可以被反驳的判断」。首图用数字，结尾必须抛观点。
- **评论是推流开关**：0 评论 → 不给第二波流量 → 帖子沉。结尾和置顶评论都要留话头，回复时别把话聊死。

**配图顺序**（5 张，按序上传，工作区 `小红书首发/` 里已按 01–05 命名）：

| # | 图 | 作用 |
| --- | --- | --- |
| 01 | 战绩 · 吃过多少 | **首图**：巨型数字 +「也没吃几家」，反差就是钩子 |
| 02 | 履历 · 走过哪些城 | 几座城、星级占比对比、偏爱口味，给信息量 |
| 03 | 1137 家是什么规模 | 回答「这个数字是相对什么而言」 |
| 04 | 三个状态怎么用 | 想去 / 吃过 / 值得二访 |
| 05 | 清单长这样 | 界面截图，证明工具真实存在 |

> 首图**用你自己的真实战绩图**，不要用演示样张——具体数字比「1137」更有说服力。
> 图里不要出现站外地址，首发的两张已经把 GitHub 小字抹掉了。

**标题**（选一个，第一个最稳；`【X】` 换成你自己的数字）：

- 数了下米其林指南，1137 家里我吃过【X】家 ← 推荐，搜索长尾最全
- 吃过【X】家米其林之后，我给自己做了张战绩单
- 米其林指南 2026 完整清单：1137 家，能自己打卡的那种
- 吃完【X】家米其林，我觉得必比登比一星更值得跑 ← 观点型，互动更强但点击略低

标题里带「米其林」「米其林指南 2026」「清单」这类搜索长尾词；系列笔记再用「城市 + 品类」结构（见下方「拆小半径」）。

**正文**（第一人称叙事，工具只占最后一段；**全文不放任何地址**）：

```
被问过好几次「你到底吃过多少家米其林」，我一直答不上来。

上个月终于认真数了一遍：【X】家，走过【N】座城。
数完顺手做了张战绩单（就是前两张），发现一件挺有意思的事：
全指南里星级占 22.6%，我吃过的里面是【P】% —— 也没特意挑，吃着吃着就偏了。

以前为什么数不清？
官方指南能按城市一家家翻，但它不知道我吃过谁；
点评和小红书的攻略是碎的，去年吃的那家，躺在收藏夹第 47 条；
自己建 Excel 更别提，1137 行，评级一变全作废。

所以把 2026 版中国大陆 + 港澳的 1137 家
（星级 257 · 必比登 439 · 入选 441，18 城）
整理成了一份能打卡的清单：
○ 想去 —— 记一句想吃哪道菜
✦ 吃过 —— 盖章，自动记日期
◎ 值得二访 —— 只有吃过的才能标，意思是「我认可，还会再去」

最喜欢一个小细节：一家店从「想去」变成「吃过」时，
它会告诉你惦记了几天。

免登录、不上传，记录只在自己手机里。
数据是一个人整理的，评级或店名有错，评论区直接说，我一条条改。

说个可能挨骂的判断：吃完这些，我觉得必比登比一星更值得专门跑一趟。
你们会为了一家店专门去一座城吗？评论区聊聊 👀

#米其林 #米其林指南 #米其林餐厅 #吃货日常 #美食打卡 #广州美食 #杭州美食
```

**评论区**（发完立刻自己占前两条，**两条都不放地址**）：

- 第 1 条 · 口径与纠错：`数字口径：2026 版指南中国大陆 + 港澳共 1137 家，星级 257 / 必比登 439 / 入选 441，18 城。一个人整理的，有错直接在这条下面说～`
  提供信息 + 邀请纠错，把「数据可能不准」变成互动入口。
- 第 2 条 · 观点钩子：`顺便问一句，你们是按星级吃还是按城市吃？我最近开始按城市扫了…`
  让评论区有对话，比「求点赞」有用得多。

> **为什么不写「链接在评论区第一条」**：平台对「引导用户离开平台」的判定覆盖笔记、图片、评论、置顶、私信和主页简介，免费分享同样不豁免；多个一手复盘里，置顶评论推产品被限流、引留言被删都有实例。这一轨的转化本来就不是目标——**用户收藏图片、参与讨论即算交付完成**，Star 交给 B 轨。要留站内入口，用主页合集或私信，不用站外地址。

**四件别做的事**：

1. 正文、图片、评论里出现任何站外地址，或写「链接在评论区」「去 XX 找我」
2. 一上来写「我做了个小工具」「开源项目求 star」——对吃货没有意义
3. 堆百万级大词（`#美食` `#探店`），新号抢不到；用 `#米其林指南` 加一两个城市词
4. 结尾停在「你吃过几家？报个数」——纯数字唤不动评论，要抛一个能被反驳的判断

**拆小半径（首篇之后立刻做）**：大合集容易高收藏、低行动——有美食矩阵复盘里，12 家店的合集拿到 3.2 万曝光 / 1900 收藏，但求地址只有 14 条、实际到店 3 人；改成「三公里三条吃法」后求地址率超过 20%。标题用「城市 + 商圈 / 品类」结构，7 天搜索流量占比从 18% 提到 44%（泛品类只有 23%）。

所以第二篇起别再发「全国 1137 家」，改成：

- 「杭州 88 家米其林里，我吃过 10 家」——城市篇，带城市词
- 「北京 6 家三星，值不值得专门跑」——品类 + 观点
- 「广州必比登 17 家，按一条地铁线排好了」——可执行半径

系列笔记用**主页合集**串起来，站内闭环，用户收藏图片就能用，不需要跳出去。

**发布时间**：周五 / 周六 20:00–22:00（美食内容周三周四晚发，周末决策咨询更高）。发完前 30 分钟留在评论区回话。

**只看四个数，别盯点赞**：

1. **封面点击率** —— 低于 6% 改首图和标题
2. **收藏率** —— 赛道基准 >3%，有人存图 = 内容有用
3. **评论条数与对话轮次** —— 决定有没有第二波流量；回复要留话头
4. **搜索流量占比** —— 长尾词有没有生效，比单篇曝光更值钱

如果 24 小时里评论几乎为 0，说明不是账号问题，是**选题没戳中**：换首图和结尾观点再发一版，别急着回去改功能。

**正文**：

```
做这个的起因很具体：想知道「我到底吃过多少家米其林」，发现没有任何地方能回答。

技术上没什么花活，几个刻意的选择：

· 构建脚本 400 多行，数据在 JSON 里，想换成黑珍珠 / 亚洲 50 最佳，改数据重跑就行

在线：https://nonlinearhuman.github.io/michelin-checklist-2026/
仓库：https://github.com/nonlinearHuman/michelin-checklist-2026

数据是一个人对着公开信息整理的，1137 条按名称核过一遍，但肯定有错，欢迎 Issue 纠错。
```

## 发布节奏

| 时间 | 轨 | 做什么 |
| --- | --- | --- |
| D0 晚 8–10 点 | A + B | 小红书首发 + 即刻（吃货流量高峰） |
| D1 上午 | B | V2EX 分享创造 + 一个豆瓣小组（先读组规） |

| D2 | A | 小红书系列第 2 篇：换成城市篇，标题带「城市 + 品类」 |

| D7 | — | 两轨分别复盘；把反馈最多的那条做成下一版；补知乎回答 |

**别一天全发完**：内容会互相淹没，而且第一天的评论你没空回。评论区的互动率直接决定平台给不给量。

## 发完之后看什么（两轨各看各的）

**A 轨**：封面点击率 >6%、收藏率 >3%、评论对话轮次、搜索流量占比。24 小时内评论几乎为 0 → 选题没戳中，换首图和结尾观点，别回去改功能。

**B 轨**：Star 增长、数据纠错条数、有没有人贴出自己的数字（「我吃了 23 家」）、评论里被问最多的是什么。

## 本轮明确不做（防止跑偏）

- **不做 Windows / 手机安装包**。现在是 135KB 单文件、双击即用、全平台通；打包要签名、审核、更新，还可能触发系统安全警告，属于降级。想要「像 App 一样」用 PWA 即可（见 README）。
- **不在小红书站内收费、不挂商品**。门槛和本轮目标都不匹配。
- **不做站外导流**。A 轨内容即交付，B 轨才放链接。
- **不改任何公开承诺**：仓库 MIT、Release 免费离线包、HelloGitHub 开源推荐、所有渠道统一「开源免费」。

## 商业化：记方向，本轮不执行

如果将来有人主动问「能不能给我一份 Excel」「能不能按城市出一版能打印的」，再考虑上架**整理好的成品**（按城市可打印清单 / Excel 模板 / 年度数据更新），而不是把网页或安装包拿去卖。别人跑通的都是卖「省事和服务」，不是卖代码。

触发条件：有人主动问，且开源免费版继续原样维护。商品口径要避开把「米其林」当商品名，并标明「非官方整理、数据仅供参考」——`LICENSE-DATA.md` 已写明不主张数据版权、与 Michelin 无关联。**本轮不执行。**

## 已知缺口（推广前最好心里有数）

1. **收集表还没有题目**（已建好、链接已接进页面底部，但创建接口只能建空表，题目要在网页上加）。
   打开 <https://docs.qq.com/form/page/DVEdqUm53VU5sRGxz> 加三个题就能用：
   - 单选「这是哪类问题」，选项：评级/名字错了 · 榜单里少了店 · 店已关门 · 功能建议
   - 填空「城市 + 餐厅名」
   - 多行「具体情况 / 你的想法」
   不加题目的话，填表的人会看到一个空白页——推流量之前务必先加。
2. **链接在微信里没有卡片预览**。微信不读 OG 标签，需要公众号或 JS-SDK；发群里时配 `og-card.png` 效果好得多。
3. **记录不跨设备**。这是刻意的取舍，一定有人问「换手机怎么办」——回答口径统一成「备份成 Excel，新设备恢复导入」。
4. **在线地址的国内可达性未验证**。GitHub Pages 在国内网络可能时好时坏；发 A 轨内容前，用手机蜂窝网络（关 WiFi）打开一次确认。完整离线包在 Release 资产里，可作为兜底。
