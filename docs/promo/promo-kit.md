## 先说判断：哪些渠道真的有用

这个项目的用户其实分两拨，目标不同，别用一套打法：

- **吃货**（要的是「我吃过多少家」）→ 走小红书，带来的是**使用量**
- **工具党 / 开发者**（要的是「这东西做得干净」）→ 走 V2EX、周刊、HelloGitHub，带来的是 **Star、纠错和长期曝光**

| 渠道 | 预期效果 | 成本 | 我的判断 |
| --- | --- | --- | --- |
| 小红书 | 使用量最大，可能带来第一条真实反馈 | 低（图已备好） | **首发，优先做** |
| 即刻 | 工具类容易被打「有用」，二次转发概率高 | 低 | **值得发**，一条即可 |
| V2EX 分享创造 | Star 与纠错的主要来源 | 低 | **值得发**，注意别写成广告腔 |
| 少数派 Matrix | 长尾强，容易被搜到、被推荐上首页 | 中（要写完整稿） | 值得投一次，用 `docs/announcement.md` 改 |
| HelloGitHub | 月刊收录后持续进 Star | 低（一个 Issue） | **值得投**，性价比最高之一 |
| 阮一峰周刊 | 单次曝光最猛，几十万读者 | 低（一封邮件/Issue） | 值得投，但要有「有意思」的角度 |
| 知乎 | 搜索长尾（「米其林打卡」「米其林 2026」） | 中 | 有空再补一个回答，不着急 |
| 微博 / 抖音 | 需要持续更新才有量 | 高 | 不建议，投入产出不划算 |

**一句话策略**：小红书拿用户，V2EX + HelloGitHub + 周刊拿 Star，少数派吃长尾。四个地方发完就可以停了，剩下的时间用来改产品。

## 1. 小红书（主力 · 0 粉冷启动版）

这一版是给**没有粉丝基础、也没有小工具上传权限**的账号写的。核心不是「介绍一个工具」，而是**发一张战绩图**。

小红书是兴趣推荐，不是粉丝分发——单篇曝光看首图和选题，不看粉丝数。10 来个粉丝照样能起量；但用这个号发「我做了一个工具」，大概率没人点。所以顺序反过来：先用战绩勾住人，工具放最后一段。

**配图顺序**（5 张，按序上传，工作区 `小红书首发/` 里已按 01–05 命名）：

| # | 图 | 作用 |
| --- | --- | --- |
| 01 | 战绩 · 吃过多少 | **首图**：巨型数字 +「也没吃几家」，反差就是钩子 |
| 02 | 履历 · 走过哪些城 | 几座城、星级占比对比、偏爱口味，给信息量 |
| 03 | 1137 家是什么规模 | 回答「这个数字是相对什么而言」 |
| 04 | 三个状态怎么用 | 想去 / 吃过 / 值得二访 |
| 05 | 清单长这样 | 界面截图，证明工具真实存在 |

> 首图**必须用你自己的真实战绩图**，不要用演示样张——具体数字比「1137」更有说服力。
> 图里不要出现站外地址，首发的两张已经把 GitHub 小字抹掉了。

**标题**（选一个，第一个最稳；`【X】` 换成你自己的数字）：

- 数了下米其林指南，1137 家里我吃过【X】家
- 吃过【X】家米其林之后，我给自己做了张战绩单
- 米其林 2026 一共 1137 家，做了份能打卡的清单

标题里带「米其林」「米其林指南 2026」这类搜索长尾词——0 粉账号的长尾搜索流量比推荐流来得更早。

**正文**（第一人称叙事，工具只占最后一段，不写成功能介绍）：

```
被问过好几次「你到底吃过多少家米其林」，我一直答不上来。

上个月终于认真数了一遍：【X】家，走过【N】座城。
数完顺手做了张战绩单（就是前两张），发现一件挺有意思的事：
全指南里星级占 22.6%，我吃过的里面是【P】% —— 也没特意挑，吃着吃着就偏了。

以前为什么数不清？
官方指南能按城市一家家翻，但它不知道我吃过谁；
点评和小红书的攻略是碎的，去年吃的那家，躺在收藏夹第 47 条；
自己建 Excel 更别提，1137 行，评级一变全作废。

所以把 2026 版中国大陆 + 港澳的 1137 家
（星级 257 · 必比登 439 · 入选 441，18 城）
整理成了一份能打卡的清单：
○ 想去 —— 记一句想吃哪道菜
✦ 吃过 —— 盖章，自动记日期
◎ 值得二访 —— 只有吃过的才能标，意思是「我认可，还会再去」

最喜欢一个小细节：一家店从「想去」变成「吃过」时，
它会告诉你惦记了几天。

免登录、不上传，记录只在自己手机里。
想用的话链接在评论区第一条，不用关注也不用私信。

你吃过几家？评论区报个数，我挺好奇的 👀

#米其林 #米其林指南 #米其林餐厅 #吃货日常 #美食打卡 #广州美食 #杭州美食
```

**评论区**（转化全靠这里，发完立刻自己占前两条）：

- 第 1 条 · 链接：`清单在这里 👉 nonlinearhuman.github.io/michelin-checklist-2026/ 手机直接开，不用下载。数据一个人整理的，有错欢迎指出～`
  用纯文本地址，**不要放可点击短链，更不要放正文里**。
- 第 2 条 · 互动钩子：`顺便问一句，你们是按星级吃还是按城市吃？我好像是走到哪吃到哪型…`
  作用是让评论区有对话，比「求点赞」有用得多。

**三件别做的事**（会直接压掉新号本来就不多的曝光）：

1. 正文放链接、图片里带站外地址
2. 一上来写「我做了个小工具」「开源项目求 star」——对吃货没有意义
3. 堆百万级大词（`#美食` `#探店`），新号抢不到；用 `#米其林指南` 加一两个城市词

**发布时间**：周五 / 周六 20:00–22:00。发完前 30 分钟留在评论区回话，互动率决定平台给不给第二波流量。

**只看三个数，别盯点赞**：

1. **收藏率** —— 有人存图 = 内容有用，比点赞值钱
2. **评论区报数字的人数** —— 说明「我也想数」这个需求是真的
3. **问「链接 / 怎么弄」的人数** —— 这才是真正的转化信号

如果 24 小时里第 2、3 项都是 0，说明不是账号问题，是**选题没戳中**：换首图和标题再发一版，别急着回去改功能。

## 3. V2EX · 分享创造

V2EX 最忌讳营销腔。写成技术取舍，反而最受欢迎：

**标题**：`把 1137 家米其林做成了一份能打卡的清单（单文件 / 无后端 / 纯 localStorage）`

**正文**：

```
做这个的起因很具体：想知道「我到底吃过多少家米其林」，发现没有任何地方能回答。
官方指南只能查餐厅，点评类平台的信息是碎的，Excel 要手动维护 1137 行。

于是把 2026 版指南中国大陆 + 港澳的 1137 家整理进来，做了个打卡清单。

技术上没什么花活，几个刻意的选择：
· 单文件产物：数据内嵌在 HTML 里，双击就能用，不用起服务
· 无后端无账号：记录在 localStorage，断网可用。代价是换设备要手动导出 Excel 再导入
· 不接地图：不含坐标和地址，只按店名 + 城市跳转搜索，省掉一堆第三方数据条款
· 构建脚本 400 多行，数据在 JSON 里，想换成黑珍珠 / 亚洲 50 最佳，改数据重跑就行

状态设计踩过一个坑：一开始「想再去」是独立于「吃过」的，
后来发现语义错了——想再去不代表去过第二次，改成「只有吃过的店才能标」才对。

在线：https://nonlinearhuman.github.io/michelin-checklist-2026/
仓库：https://github.com/nonlinearHuman/michelin-checklist-2026

数据是一个人对着公开信息整理的，1137 条逐条核过，但肯定有错，欢迎 Issue 纠错。
```

**别一天全发完**：内容会互相淹没，而且第一天的评论你没空回。评论区的互动率直接决定平台给不给量。

## 发完之后看什么

不看 Star，先看这三个：

1. **有没有人贴出自己的数字**（「我吃了 23 家」）—— 说明产品被用起来了
2. **有没有人报数据错误** —— 说明真的在核对，这是最值钱的反馈
3. **评论里被问最多的是什么** —— 那就是下一版该做的功能，而不是我猜的功能

## 三个已知缺口（推广前最好心里有数）

1. **收集表还没有题目**（已建好、链接已接进页面底部，但这个 API 只能建空表，题目要在网页上加）。
   打开 <https://docs.qq.com/form/page/DVEdqUm53VU5sRGxz> 加三个题就能用：
   - 单选「这是哪类问题」，选项：评级/名字/地址错了 · 榜单里少了店 · 店已关门 · 功能建议
   - 填空「城市 + 餐厅名」
   - 多行「具体情况 / 你的想法」
   不加题目的话，填表的人会看到一个空白页——推流量之前务必先加。
2. **链接在微信里没有卡片预览**。微信不读 OG 标签，需要公众号或 JS-SDK 才行；
   发群里时配一张图效果好得多。
3. **记录不跨设备**。这是刻意的取舍，但一定有人问「换手机怎么办」——
   回答口径统一成：「备份成 Excel，新设备恢复导入」，README 和页面底部都写了。
